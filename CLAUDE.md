## Project Overview

Swiftfin is a SwiftUI video client for Jellyfin media server, targeting iOS 16+ and tvOS 17+. VLCKit handles broad codec support; native AVKit is an alternative player. The codebase splits into shared backend logic and platform-specific views. Both iOS and tvOS builds must pass for PRs.

Note: [Jellyfin's LLM/AI Development Policy](https://jellyfin.org/docs/general/contributing/llm-policies/) applies to all contributions.

## Build & Dependencies

```sh
# Install tools (first time)
brew install carthage swiftformat swiftgen

# Install/update Carthage dependencies (VLCKit)
carthage update --use-xcframeworks

# Build iOS
xcodebuild -scheme "Swiftfin" -destination "platform=iOS Simulator,name=iPhone 16,OS=18.5" build

# Build tvOS
xcodebuild -scheme "Swiftfin tvOS" -destination "platform=tvOS Simulator,name=Apple TV,OS=18.5" build

# Lint (must pass for PRs)
swiftformat .

# Generate localized strings
swiftgen
```

SPM handles most dependencies (resolved by Xcode). Carthage handles only VLCKit (`Cartfile`). No test targets exist in the project.

Set your dev team in `XcodeConfig/DevelopmentTeam.xcconfig` (gitignored):

```
DEVELOPMENT_TEAM = "YOUR_TEAM_ID"
PRODUCT_BUNDLE_IDENTIFIER = org.jellyfin.swiftfin
```

## Architecture

### Directory Structure

- **`Shared/`** — All cross-platform code (iOS + tvOS share this)
  - `Services/` — Business logic, networking, download management, user session, keychain
  - `ViewModels/` — Stateful logic for views (MVVM pattern)
  - `Coordinators/` — Navigation via custom coordinator pattern
  - `Components/` — Reusable SwiftUI components
  - `Extensions/` — Swift/SwiftUI/JellyfinAPI extensions
  - `SwiftfinStore/` — CoreStore-based persistent storage with versioned schemas (V1→V2 migration)
  - `Strings/Strings.swift` — Auto-generated by SwiftGen from `Translations/en.lproj` — **do not edit manually**
- **`Swiftfin/`** — iOS app: views, app entry point, iOS-specific components
- **`Swiftfin tvOS/`** — tvOS app: same structure, tvOS-specific views

Views for the same screen often exist in both `Swiftfin/Views/` and `Swiftfin tvOS/Views/` sharing the same ViewModel. Platform conditionals use `#if os(iOS) ... #else ... #endif`.

### Navigation & Coordinators

Hierarchical coordinator-based navigation (`Shared/Coordinators/`):

- **RootCoordinator**: Top-level state machine. States: `appLoading` → `selectUser` or `serverCheck`(iOS)/`mainTab`(tvOS). Subscribes to `didSignIn`/`didSignOut` notifications for state transitions.
- **TabCoordinator**: Manages tab selection, each tab owns a `NavigationCoordinator`.
- **NavigationCoordinator**: Manages push/sheet/fullscreen stacks via published `path` and `presentedSheet`/`presentedFullScreen` arrays.
- **NavigationRoute**: Lightweight value type with static factory methods split across `NavigationRoute+Feature.swift` files. Supports custom transition styles.

### Dependency Injection (Factory)

Services are registered as container extensions in their respective files:

```swift
extension Container {
    var downloadManager: Factory<DownloadManager> { ... }.shared
}
```

Scopes: `.shared` (per-container), `.singleton` (global), `.cached` (resettable). Injected via `@Injected(\.serviceName)` in ViewModels and Services.

### ViewModel Pattern

All ViewModels extend a `ViewModel` base class (`Shared/ViewModels/ViewModel.swift`):

- Marked `@MainActor`, conforms to `ObservableObject`
- Injects `dataStore`, `keychainService`, `currentUserSession` via Factory
- Uses `@Published` properties for SwiftUI reactivity
- `BaseFetchViewModel` adds async data fetching with `@Stateful` macro and `@CasePathable enum Action`

### Authentication & Session

- **UserSession**: Immutable container holding authenticated `JellyfinClient`, `ServerState`, `UserState`. Created at sign-in, cached via Factory.
- **Flow**: RootCoordinator checks `Defaults[.lastSignedInUserID]` → fetch from CoreStore → create UserSession → navigate to main content.
- **Notifications**: Typed notification system (`Shared/Services/Notifications.swift`) with `Notifications[.key].post()` / `.publisher` / `.subscribe()`.

### Persistence (SwiftfinStore)

CoreStore-based with versioned schemas:

- **V2 Models**: `ServerModel`/`ServerState`, `UserModel`/`UserState`, `AnyData` (generic key-value store)
- **StoredValues**: Arbitrary Codable data stored per domain/key/owner combo
- **Setup**: Async `setupDataStack()` in RootCoordinator at launch

## Key Libraries

- **Factory** — DI (`@Injected(\.service)`)
- **JellyfinAPI** (jellyfin-sdk-swift) — Jellyfin server API client
- **Defaults** — UserDefaults wrapper for app settings
- **VLCUI** — SwiftUI wrapper around VLCKit for video playback
- **Nuke** — Image loading/caching
- **Pulse** — Network logging
- **CoreStore** — Core Data wrapper for persistent storage
- **CollectionHStack/CollectionVGrid** — Custom collection layout views (via Transmission package)

## Code Style

- SwiftFormat config in `.swiftformat` (v0.59.1, Swift 6.2 compat)
- Max line width: 140 chars
- `// MARK:` comments for code organization (encouraged)
- MPL 2.0 license header auto-inserted by SwiftFormat
- All user-facing strings must be localized (via `Translations/en.lproj`)
- Extension-based organization: split large types across `Type+Feature.swift` files
- Protocol-based services for mockability (especially in Download system)
